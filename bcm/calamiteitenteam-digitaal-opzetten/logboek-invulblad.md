# Logboek van het digitale calamiteitenteam: invulblad

> Leeg invulblad voor de centrale vastlegging tijdens een digitale calamiteit: feiten, besluiten, acties, communicatie
> en meldingen. Het logboek is het enige ware overzicht van het calamiteitenteam en de bron voor de evaluatie, de
> verantwoording en een eventueel extern onderzoek. Hieronder staan de vier onderdelen met hun kolommen en keuzelijsten;
> zet ze in je eigen spreadsheet of logboektool. Hoe je het logboek bijhoudt, staat in het
> [logboekformat](logboekformat.md).

## Instructie

| | |
|---|---|
| Wie vult in | De secretaris van het calamiteitenteam of de loghouder die de voorzitter aanwijst. De actuele bezetting staat in het calamiteitenplan (sectie bereikbaarheid). |
| Bij activatie | Sla het lege invulblad eerst op onder een eigen naam: `Logboek calamiteitenteam - <korte incidentnaam> - <jjjj-mm-dd>`. Werk nooit in het lege invulblad zelf. |
| Werkwijze | Registreer doorlopend en met exacte tijdstippen. Overschrijf een eerdere regel nooit; voeg een nieuwe regel toe met de correctie. Nummer de sleutelbesluiten door en verwijs er vanuit de logboekregels naar. |
| Waarom de meldketen apart staat | De Cyberbeveiligingswet werkt met termijnen die lopen vanaf het moment van kennisname (T0). Dat moment, en de vastlegging ervan, is waarmee je tijdigheid aantoont richting de bevoegde autoriteit. De termijnen lopen per gemeente en ook in avonden en weekenden. |
| Verhouding tot het incidentsysteem | Het incident zelf blijft geregistreerd in het servicemanagementsysteem. Dit logboek registreert de coördinatie en de besluitvorming van het calamiteitenteam. Neem het incidentnummer over, zodat beide sporen aan elkaar te koppelen zijn. |
| Na afloop | Bewaar het logboek in het teamdossier en deel het met de bedrijfscontinuïteitsorganisatie voor de evaluatie. |

## 2. Meldketen (wettelijke termijnen per gemeente)

Elke gemeente is een zelfstandige entiteit met een eigen meldplicht, dus per gemeente een eigen regel. T0 is het moment
van kennisname. Vul zelf T0 en de verzendmomenten in; de deadlines reken je uit T0.

| Kolom | Inhoud |
|---|---|
| Gemeente | één regel per gemeente |
| T0: kennisname | datum en tijd |
| T0 vastgesteld door | rol |
| Incidentnummer | uit het servicemanagementsysteem |
| Significantietoets door | rol |
| Uitkomst toets | Meldplichtig, Niet meldplichtig of Nog te bepalen |
| Drempel(s) | welke drempel is geraakt |
| Deadline waarschuwing | T0 + 24 uur |
| Waarschuwing verzonden | datum en tijd |
| Referentie NCSC | kenmerk van de melding |
| Deadline melding | T0 + 72 uur |
| Melding verzonden | datum en tijd |
| Eindverslag uiterlijk | gerekend vanaf de melding van 72 uur |
| Eindverslag verzonden | datum en tijd |
| Melding verricht door | rol |
| Contactpersoon gemeente geïnformeerd | Ja, Nee of Niet van toepassing |
| Informatieplicht beoordeeld | Ja, Nee of Niet van toepassing |

Let op: het eindverslag loopt volgens de procedure vanaf de melding van 72 uur en niet vanaf T0. Leg bij een detectie die
meerdere gemeenten raakt per gemeente vast welk moment als T0 geldt.

|---|---|---|---|---|---|---|---|---|---|---|---|---|
| SB-01 | | | | | | | | | | | | |
